// ===== アニメーション =====
unityのanimationは純粋な座標移動ではないので、いったん見送る
代わりに、Scalixのシステムもしくは補助ツールのシステムで、構造を推測し自動でanimationを適用する
例えば、足などの場所をglTFのデータから正規表現や、tree構造などで推測し、歩行animatinなどをscaleし適用する
この場合の歩行animationは汎用的なものを使う 例えばsinだとか もっと自然なものも作れるだろうが、それは将来
汎用的というのはavater側で操作するのではなく、Scalixのsystemが自動で適用する
このため、avaterは人型想定とする

物理演算は個人単位で停止可能 VR状態では自動で停止してもいいかもしれない しかし、それだと臨場感が...

その場合、手を押し戻されても体ごと下がらないとavaternode間の位置関係がおかしなことになるか?

// ===== 計算資源の効率的な分配 =====
まず基本構造は中央集権型 VRCと変わらない
しかし、計算用機器には、clientが必須ではない処理(描画は必須)などの分配を想定
	-> 分散は難しいので、まず1台想定で作ってから分散システムに発展させる
管理コンピュータは計算を行わない 計算系機器含めすべてに従わせる
まずはLAN想定 WANでもbittorrentなどはポート開放無しで動作しているので理論上可能なはず
最初はLAN想定の中でも、serverはlocalserverで立ち上げる
この計算の分離は、ある程度基盤が完成してからでもいいかもしれない

// ===== 通信の暗号化 =====
暗号化システムにはEAD7のデータ構造を使ってもいいかもしれない
管理コンピュータ<->演算機器の通信はスピードが要求される訳ではないので、 速度 <<<<< 安全性 の設計
client間はバランスを考える必要がある
セキュリティ面は正直言って大変なので、基盤が完成してから

// ===== OSS =====
データ入出力には極力標準的な規格を使い、import&exportは外部OSSに任せる
これによってscalix内部の最適化に注力できる
tinygltf(glTF)やOpenXR(VR)など

// ===== 外部データ =====
標準的な規格を窓口に、既存のデータを最大限活用する
それらの資産を活用できないようではScalix周辺の発展は見込めない
勿論内部表現は持つが、interfaceは標準的な規格のデータ

worldはsystem内部では分割しつつも、連続した世界を作りたい そっちの方が現実味あるじゃん?
